What the system calculates

Astro Global separates the product interface from the calculation engine. The web shell is a thin client for a FastAPI backend that returns planetary states, resonance search, scoring, coverage, confidence and summaries.

Ephemeris

Planetary calculations are handled by Swiss Ephemeris through the Python backend. The browser shell must not become the source of planet positions, aspects, cycles or rarity.

Historical data

Historical events come from a curated backend dataset with sources. The current reliable layer starts at 1500. Earlier 1000-1500 history is planned as a separate deep-history layer with lower confidence handling.

AI boundaries

AI is not a planet calculator and is not a source of facts. It may only describe backend results. It must not add events, sources or claims outside the data returned by the API.

Matched vs context

Direct historical matches and broad contextual processes are separated in the model as matched events and context events. The interface must keep that distinction visible.

Limits

Similarity is not prediction. Coverage, source quality and confidence labels are part of the result. Thin historical coverage or out-of-range requests should be treated as warnings, not hidden.

Sources

Source links are returned with backend event data. The interface should show them close to the matched or context event they support, not as unsourced narrative claims.

GitHub

Public code and issue tracking are planned around the Astro Global GitHub repository. Production secrets, local indexes and private data must not be published.

Public demo blockers

  • Production token, CORS, rate limit and request-size guardrails must stay enabled.
  • Swiss Ephemeris licensing must be reviewed before public distribution or commercial use.
  • AI cost limits and abuse monitoring must be active before generated narrative features.
  • Private env files, caches, indexes, exports and local data must never be published.
